# deepThinkCar-mini: AI와 단계적으로 진행한 조립·학습·주행 기록

- 기록일: 2026-08-10
- 대상 저장소: `Alpenj/deepThinkCar_mini`
- 작업 브랜치: `agent/deepthinkcar-step2-5-safety`
- 성격: 실물 프로젝트 진행 기록 + 재현 가능한 소프트웨어 검증

이 프로젝트는 AI가 자동차를 대신 만든 결과가 아니다. 사람이 키트를
조립하고 트랙과 안전 조건을 판단했으며, AI는 문서를 따라 다음 한
단계를 정리하고, 실행 명령을 만들고, 오류를 좁히고, 결과를 기록하는
보조 역할을 맡았다. 작은 단계마다 실제 출력과 파일을 확인한 뒤 다음
단계로 넘어가는 방식으로 진행했다.

## 1. 실물 하드웨어 조립

먼저 키트 구성품과 별도 준비물을 나눴다. 라즈베리파이 보드, OS가 든
SD 카드, 보호회로와 KC 인증이 있는 65 mm 18650 배터리는 키트 외 준비
항목이다. 아크릴 판은 강하게 조이면 깨질 수 있어 서보와 스페이서를
먼저 가볍게 고정하고 마지막에 정렬을 확인하는 순서로 접근했다.

조립 흐름은 다음과 같았다.

1. 상판에 앞바퀴 조향 서보와 연결 부품을 장착했다.
2. 라즈베리파이/HAT용 스페이서를 먼저 세웠다.
3. 배터리 홀더와 카메라 마운트를 상판에 연결했다.
4. 하판에는 좌우 DC 기어드 모터와 바퀴를 방향에 맞춰 장착했다.
5. 앞바퀴 조향 링크, 상·하판, 라즈베리파이, 카메라와 모터 배선을 연결했다.

AI는 부품 순서를 체크리스트로 바꾸고, 다음 작업 전에 필요한 부품과
주의점을 짧게 확인하는 데 사용했다. 실제 나사 체결, 배선 방향, 바퀴
간섭 여부는 사람이 눈으로 확인해야 했다.

## 2. OS·카메라·모터·서보 점검

라즈베리파이 환경에서 카메라, OpenCV, TensorFlow, ServoKit을 사용할 수
있게 준비하고, 바로 주행시키지 않고 부품별 테스트부터 진행했다.

- 카메라: 320×240 프레임이 연속으로 들어오는지 확인
- DC 모터: 좌우 방향과 정지 명령을 낮은 출력에서 확인
- 서보: 90° 부근에서 시작해 기구 간섭 없는 안전 범위를 확인
- 중앙값: 모터 전원을 끈 상태에서 직진 중앙값을 맞춘 뒤 저장

소프트웨어 쪽에는 카메라 오류, 차선 손실, 추론 예외, 루프 정지 시
모터를 멈추는 fail-safe와 watchdog을 추가했다. 실제 출력은 `--drive`를
명시했을 때만 허용하고, 기본 실행은 모터와 서보를 움직이지 않는
dry-run으로 만들었다.

## 3. OpenCV 차선 추종과 데이터 수집

첫 주행 기준은 딥러닝이 아니라 OpenCV였다. 검은 테이프 두 줄에서
관심영역을 자르고 선분을 찾은 뒤 차선 중앙으로 조향각을 계산했다.
OpenCV는 왜 그런 각도를 냈는지 화면에서 확인하기 쉬워, 조립 직후의
카메라 위치와 서보 중앙값을 조정하는 기준으로 유용했다.

주행 중 원본 AVI를 저장하고, 후속 단계에서는 원본을 덮어쓰지 않는
별도 디렉터리에 PNG와 manifest를 만들었다. 2026-08-07 영상의 결과는
405프레임 중 278장 라벨 성공, 127장 차선 미검출이었다. 라벨 범위는
60~138°, 평균 94.15°였다. 이 라벨은 OpenCV가 계산한 pseudo-label이라
검출기의 편향을 그대로 배울 수 있다는 한계를 함께 기록했다.

## 5. 현재 환경에서 다시 학습

기존 notebook을 그대로 실행하는 대신 현재 Keras 3에서 재현 가능하게
정리된 CLI를 사용했다. 프레임 번호를 20장 단위 temporal group으로
묶어 인접 프레임이 학습과 검증에 섞이는 문제를 줄였고, 학습 이미지만
좌우 반전해 조향각을 `180 - angle`로 바꿨다. 목표값은
`(angle - 90) / 90`으로 정규화했다.

```bash
python3 PC_run_code/jd_deep_learning.py \
  --data-dir PC_run_code/data \
  --output-dir PC_run_code/output/jtjin0916_deepcar_20260810_seed20260810 \
  --epochs 50 \
  --batch-size 32 \
  --validation-fraction 0.2 \
  --temporal-group-size 20 \
  --seed 20260810
```

RTX 5050 Laptop GPU를 다른 학습 작업과 함께 사용했다. TensorFlow가
compute capability 12.0a용 사전 컴파일 커널을 포함하지 않아 PTX JIT
경고가 있었지만, XLA/cuDNN 경로로 학습은 정상 완료됐다. 260장은 학습,
69장은 검증에 사용했고 좌우 반전 후 학습 수는 520장이었다. 50 epoch를
요청했지만 early stopping으로 21 epoch에서 종료됐으며 최적은 11 epoch였다.

| 모델 | 같은 69장 MAE | RMSE | 해석 |
| --- | ---: | ---: | --- |
| 새 후보 | 4.93° | 6.00° | 이번 분할에서 학습하지 않은 group 평가 |
| 현재 `models/` 기본 모델 | 14.93° | 17.44° | 이 데이터 분포에는 잘 맞지 않음 |
| 원본 PC 출력 모델 | 1.91° | 2.39° | 같은 329장을 이미 봤을 가능성이 있어 누수 배제 불가 |

새 후보 H5의 SHA-256은
`d3d9cb90f53175d47c1f90cf8555d734f280c130387ac5e37b2a75b58c165a7d`다.
저장 직후 재로드 검증도 통과했다. 검증 각도는 90~113°에 치우쳐 있어
왼쪽 급회전 일반화까지 증명하지는 못한다.

## 6. 녹화 영상으로 주행 루프 확인

후보 모델을 기본 모델로 복사하지 않고 경로를 명시해 headless 영상
추론을 실행했다. `--drive`를 넣지 않았으므로 실제 GPIO·서보 출력은 없다.

```bash
python3 jd_4_lane_follower_deep.py \
  --model PC_run_code/output/jtjin0916_deepcar_20260810_seed20260810/lane_navigation_candidate.h5 \
  --video data/car_video.avi \
  --headless \
  --max-frames 200
```

warm-up 이후 유효 190프레임을 처리했고 예측 21회, 카메라 오류 0,
watchdog timeout 0, cleanup error 0으로 종료했다. 해당 영상에서는
lane-ready 비율이 11.1%로 낮았으므로 모델 승격 근거로 사용하지 않았다.

이전 실차 관찰에서는 당시 학습 후보가 OpenCV 경로보다 트랙을 잘 따라가지
못했다. 그 결과도 숨기지 않고 모델을 후보로만 남겼다. 현재까지의 핵심
성과는 “한 번 움직였다”가 아니라, 결과가 나쁠 때 기본 모델을 자동으로
교체하지 않고 원인과 다음 시험 조건을 남기는 흐름을 만든 것이다.

## 7. AI가 실제로 도운 부분

- 긴 조립·주행 문서를 바로 다음에 할 수 있는 체크리스트로 줄였다.
- 카메라/모터/서보 문제를 한꺼번에 고치지 않고 부품별로 나눠 확인했다.
- 원본 영상과 기존 데이터를 지우지 않는 출력 구조로 코드를 바꿨다.
- 최신 Python/Keras에서 깨진 H5 로딩과 학습 API를 현재 방식으로 고쳤다.
- temporal group 분할, 해시, 검증 CSV, 모델 비교 JSON을 남겼다.
- 실제 모터 출력 전 dry-run, calibration, watchdog, cleanup gate를 넣었다.
- 실패한 후보를 성공처럼 포장하지 않고 기본 모델 승격을 보류했다.

사람이 맡은 부분은 실물 상태 판단, 전원과 배터리 안전, 트랙 설치,
비상 정지 준비, 실제 주행 관찰, 그리고 최종 모델 승격 결정이다.

## 8. 검증과 다음 주행 계획

이번 추가 변경의 학습·평가 테스트 9개와 저장소 전체 `test_code` 61개가
통과했다. 후보 모델은 학습, H5/Keras 저장, H5 재로드, 같은 검증셋의
3개 모델 비교, 녹화 영상 headless 실행까지 확인했다.

다음 실차 시험은 아래 순서로 제한한다.

1. 좌우 회전이 균형 잡힌 새 영상을 촬영해 독립 검증셋으로 고정한다.
2. 바퀴를 든 상태에서 중앙값, 안전 각도, watchdog, 비상 정지를 확인한다.
3. 현재 OpenCV 경로를 속도 20%로 짧게 실행해 기준 주행을 기록한다.
4. 기본 모델과 후보를 같은 트랙·배터리·카메라 조건에서 비교한다.
5. 차선 유지율과 정지 동작이 기준을 넘을 때만 후보 승격을 검토한다.
6. 객체 정지는 실제 표지판의 거리별 검출과 정지 거리를 별도 측정한다.
